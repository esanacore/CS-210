# CS-210: Corner Grocer Item Tracking Program

[![C++ Smoke Test](https://github.com/esanacore/CS-210/actions/workflows/cpp-smoke-test.yml/badge.svg)](https://github.com/esanacore/CS-210/actions/workflows/cpp-smoke-test.yml)

Archived coursework for **SNHU CS-210 Programming Languages**.

This repository contains Project Three, a C++ command-line program for "The Corner Grocer." The program reads a daily purchase record, counts how often each produce item appears, writes a frequency backup file, and lets a user query or display the results through a simple menu.

## Portfolio Context

This is a preserved coursework submission. The C++ source is intentionally kept as submitted so the repository can show the work in its original academic context. Repository polish, documentation, and automation have been added around the submission to make the archive easier to review.

The goal of this archive is to show:

- applied C++ fundamentals
- file input/output
- maps and frequency counting
- menu-driven CLI interaction
- input validation and exception handling
- iterative improvement in repository presentation over time

## Features

- Loads grocery purchase records from `CS210_Project_Three_Input_File.txt`
- Counts item frequencies with a `std::map`
- Writes frequency results to `frequency.dat`
- Looks up the frequency of a requested item
- Prints all item frequencies
- Prints a text histogram
- Handles invalid menu input

## Build And Run

From the repository root:

```bash
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp GroceryAnalyzer.cpp -o corner-grocer
./corner-grocer
```

On Windows with MinGW:

```powershell
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp GroceryAnalyzer.cpp -o corner-grocer.exe
.\corner-grocer.exe
```

The program expects `CS210_Project_Three_Input_File.txt` to be in the same directory as the executable.

## Smoke Test

The GitHub Actions workflow compiles the project and runs a minimal menu-exit smoke test:

```bash
printf "4\n" | ./corner-grocer
```

This verifies that the archived source still builds and launches without changing the submitted code.

## Known Limitations

- The submitted loader reads grocery entries with token-based input, so the included input file is expected to contain one item name per token.
- `frequency.dat` is generated by the application and is also kept in the repository as a sample output artifact.
- The project is intentionally not refactored here. Any modernization should happen in a separate branch, folder, or follow-up note so the original submission remains available.
